# 演示操作手册

## 演示前准备（每次演示必做）

```bash
uv run python scripts/reset_demo.py --snapshot initial   # 输出 RESET_OK
uv run python scripts/validate_data.py                   # 输出 VALIDATION_OK baseline=LLD-724_1
uv run streamlit run streamlit_app.py --server.headless true
```

- 重置与应用互斥：应用运行中执行重置返回 `RESET_LOCKED`；请先停止应用（或关闭其进程）再重置。
- 连续三次「重置 → 校验 → 完整流程」无阻断是本版本的交付门禁之一（见测试报告第四节）。

## 两个演示快照

| 快照 | 内容 | 用途 |
| --- | --- | --- |
| `initial` | 基线 `LLD-724_1` 生效、两张知识卡、基线来源归档 | 完整治理流程演示的起点 |
| `frozen` | 在 initial 基础上附带冻结缓存（导入 / 查询 / 自检） | 离线或弱网演示：查询页可选择「冻结缓存」直接命中 |

## 演示主线（对应应用六个页面）

1. **首页**：当前基线 `LLD-724_1`、项目问题总览。
2. **导入**：上传风险意见材料（`txt/md/pdf/docx`，≤20MB），实时分析产出候选 / 冲突条目及来源引用。
3. **查询**：提问（如「当前目标客群是什么？」），回答附基线版本与引用；查询方式可选「实时查询 / 冻结缓存」，缓存命中时展示「冻结缓存 · 缓存生成时间」。
4. **自检**：一键自检发现冲突 / 缺失等问题，重大问题双引用。
5. **决定与变更单**：人工接受迭代意见，生成变更单并查看发布 Diff。
6. **审批与发布**：人工审批后原子发布，基线演进为 `LLD-724_2`；**追溯**页查看六节点完整主链。

## 演示注意事项

- 发布后立即全量自检会被 25% 出站覆盖率预算按设计阻断（`OUTBOUND_COVERAGE_EXCEEDED`）；先导入新材料再自检，或将其作为治理行为讲解点。
- 冻结缓存要求「同材料、同版本」精确键匹配；基线发布后旧查询缓存自动失效。
- 演示窗口建议 1440×1024、浏览器缩放 100%（UI 验收基线，证据见 `docs/qa/ui-1440x1024/`）。
