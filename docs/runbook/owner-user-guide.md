# 产品文档孵化器 2.2 Owner 使用说明

本产品只有一个角色：Owner（产品经理）。你可以在本机为不同产品分别建立项目目录，归档材料，形成 Wiki，再孵化、确认并发布产品文档。

## 创建项目和选择位置

1. 打开“项目中心”，填写项目 ID、名称和说明。
2. 选择项目的父目录。最终项目目录固定为“所选父目录/项目 ID”；不同项目可以放在不同父目录。
3. 创建成功后，项目目录会包含 `raw/`、`wiki/`、`schema/`、`exports/`、`README.md` 和 `AGENTS.md`。可将该项目根目录直接作为 Obsidian Vault 打开。

不要选择已有同名项目目录。系统不会覆盖或合并其中已有文件。

## 项目目录被移动后的处理

如果项目文件夹被整体移动，项目中心会显示“路径不可用”。在该项目的重新定位区域，选择移动后的项目根目录。目录名和内部项目身份必须与当前项目一致；确认后可继续归档和 Ingest。2.2 不支持直接迁移到另一台电脑。

## 归档原始材料

在“原始材料”选择或拖入一个文件，补全材料分类、权威级别、安全等级及版本信息，然后点击“确认归档”。系统会复制一份文件到项目内的 `raw/`，原文件不会被修改。

归档后的状态是 `pending_ingest`，表示材料已安全留存，但还没有进入 Wiki，也还不能用于产品文档孵化。

## 让材料进入 Wiki

- L1/L2：已脱敏并允许外部调用的材料，可以点击“开始 Ingest”。系统会生成来源页、主题页、索引和日志。成功后状态为 `ingested`。
- L3/L4：不会发送给外部模型。点击“准备本地草稿”，在生成的本地 Markdown 草稿中补写来源摘要和主题内容，可用 Obsidian 编辑。完成后回到页面点击“确认本地 Ingest”。确认成功前，这些材料不能参与孵化。

Ingest 失败时，页面会显示安全错误码；修正材料或草稿后按页面提示重新执行。归档的原始材料、当前已发布文档和历史版本不会因 Ingest 被覆盖。

## 从 Wiki 孵化产品文档

打开“文档孵化”，只能选择已完成 Ingest 的来源。系统读取其 Wiki 页面，而不是直接读取 Raw 原文件，生成候选产品文档。检查候选内容、引用、冲突和证据缺口后保存并发布。

发布后，当前生效文档位于 `wiki/current/当前产品方案.md`，历史版本保存在 `wiki/versions/`。在“当前产品”可下载当前版本的 Markdown 文件；下载内容不包含 Raw 或其他项目资料。
