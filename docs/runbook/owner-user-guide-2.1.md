# 产品文档孵化器 2.1 Owner 使用说明

本产品目前只有一个角色：Owner（产品经理）。Owner 负责创建项目、归档材料、生成候选、确认发布和下载当前产品文档。

## 一次完整使用流程

1. 在“项目中心”新建或切换项目。系统会在本地项目库创建 `raw/`、`wiki/`、`schema/`、`exports/` 与 `.incubator/` 目录。
2. 打开“原始材料”，从浏览器选择一份 `.md`、`.txt`、`.pdf` 或 `.docx` 文件。选择文件本身不会写入项目库；只有点击“确认归档”才会复制一份到当前项目的 `raw/`。
3. 填写材料名称、显示版本、来源部门和文档日期；选择“新材料”或“新版本”。“新版本”必须由 Owner 手工选择要关联的材料系列，避免仅凭相似文件名误判。
4. 从固定材料类型中选择一项：产品需求、业务规则、交互原型、流程说明、数据口径、合规风控、运营策略或项目资料；再选择权威级别“正式基线依据”或“参考材料”。
5. 选择安全等级并确认是否已脱敏。只有已脱敏、允许外部调用、且为 L1/L2 的材料才能供外部文档工作流使用。L3/L4 不会发送给外部模型。
6. 对 L3/L4 材料，可在材料列表使用“与当前方案对照”或“创建本地候选”。两项操作都在本机完成；发布前系统会再次核验来源原件完整性。
7. 在“文档孵化”生成或查看候选草稿；经 Owner 确认后发布。发布后的唯一当前版本位于 `wiki/current/当前产品方案.md`，同时保存不可变历史版本。
8. 在“当前产品”下载当前生效版本的 `.md` 文件。导出只包含当前产品文档，不会打包原始材料或其他项目内容。

## 常见概念

- **SHA-256**：按文件内容计算的唯一校验值。它用于发现文件是否被改动，不用于判断两份材料是否是同一业务文件。
- **显示版本**：便于人阅读的版本号，如 `V1.2`；是否为同一材料的版本由 Owner 手工关联材料系列决定。
- **正式基线依据**：可作为当前方案的正式依据；**参考材料**：提供背景或思路，但不直接决定方案。
- **新旧内容 Diff**：候选或当前文档之间的新增、删除和修改内容对比。

## 调整迁移材料

旧项目迁入的材料可能保留历史分类。使用材料列表中的“调整历史材料分类”可把它映射为固定类别。此操作只改分类元数据并留下审计记录，归档文件、归档路径和 SHA-256 均不变。

## Owner 发布前检查

确认材料系列关联正确；确认 L1/L2 外部调用材料已脱敏；确认 L3/L4 未被发送到外部模型；确认候选版本的 Diff 与引用材料符合预期。若系统提示 `PUBLISH_SOURCE_INTEGRITY_FAILED`，请先恢复被改动或缺失的原始归档文件，再重新发布。
