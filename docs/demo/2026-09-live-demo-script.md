## 异常预案（现场口播）

- **实时调用超时/失败**（如网络抖动）：页面明确提示「实时分析超时」；查询页与自检页自动探测完全匹配的冻结缓存，命中则以缓存继续（标注「冻结缓存」、缓存生成时间与当前基线版本），未命中明确告知「未找到同材料、同版本的可用缓存」，绝不使用近似缓存。导入页选择「冻结缓存」方式重传同一材料可继续（已按 T13 实证）。
- **Dify 三个 Key 任一失效**：只有存在完全匹配（同材料、同版本、同问题）冻结缓存的任务可按缓存口径继续——即导入页缓存重传 `risk_opinion.md`、查询页缓存提问「当前目标客群是什么？」、自检页对同一来源缓存自检（均已在 frozen 快照冻结并实证）。无完全匹配缓存的环节不得继续，不得把首页浏览、本地确定性检查等本地能力表述为语义模型的等价替代；按预检清单第 4 项在开场前发现时，先按冒烟规程验证对应缓存可从 UI 命中，缓存也不可得则改用备用演示视频。
- **任何页面异常**：执行 `uv run python scripts/reset_demo.py --snapshot initial`（P95 0.32s）回到初始基线，按脚本从 00:45 继续；两次连续异常则播放备用演示视频（视频工件不随仓库分发，由现场负责人在演示设备上预置并按预检清单第 8 项补证）。
